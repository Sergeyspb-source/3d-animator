# Как мы решали задачи

Здесь лежат разборы задач проекта: что сломалось или чего не хватало, почему, что пробовали и чем кончилось.
Из этих разборов делаются ролики для YouTube. Поэтому пишем так, чтобы понял человек, который играет в игры,
но ни разу не открывал Blender.

Образец: [2026-11-24_fast-hunyuan-shape](2026-11-24_fast-hunyuan-shape/README.md).

## Кто и когда пишет

- Каждая ветка (сессия Claude) пишет разбор в конце своей задачи. Завершённые ветки пишут задним числом.
- Одна папка — одна задача. Если ветка решила две разные задачи, у неё две папки.
- Если задачу делали несколько веток, пишет та, что довела её до результата, и называет остальных.
- Если задача решена не до конца, разбор всё равно нужен, со статусом «частично» или «не решено». Тупики зрителю
  интересны не меньше побед.

## Папка

Имя папки: `ГГГГ-ММ-ДД_коротко-латиницей`. Дата — день, когда решение заработало. Например `2026-11-24_fast-hunyuan-shape`.

```
2026-11-24_fast-hunyuan-shape/
  README.md    рассказ (шаблон: _template/README.md)
  case.json    данные для монтажа (шаблон и описание полей: _template/)
  img/         картинки рассказа, попадают в git
  src/         крупные чистые кадры и ролики, остаются только на диске (в .gitignore)
```

## Рассказ (README.md)

Возьмите `_template/README.md` и сохраните порядок разделов:

1. Заголовок-вопрос и одна фраза-крючок.
2. Коротко в три строки: было, стало, как.
3. Картинка «до/после».
4. Что было не так.
5. Почему так происходило.
6. Что пробовали, включая неудачи.
7. Как решили.
8. Как проверили, цифры.
9. Что осталось.
10. Словарик.
11. Для видео: текст для озвучки, вау-момент, обложка.
12. Для любопытных: файлы, коммиты, ветки.

### Как писать

- Пишите как другу-геймеру: короткие предложения, одна мысль в предложении.
- Каждый термин объясняйте при первом появлении и вносите в словарик. Например: «Децимация — упрощение модели: из
  400 тысяч треугольников оставляем 50 тысяч».
- Сравнения из жизни приветствуются. Например: «UV-шов — как шов на выкройке одежды».
- Код, пути и названия функций пишите только в последнем разделе «Для любопытных». В основном тексте — то, что видно глазами.
- Цифры — только измеренные, и с указанием, на чём мерили (RTX 4060, 8 ГБ). Если оценивали без замера, так и пишите: «на глаз».
- У времени пишите, первый это запуск или повторный. Первый бывает в разы дольше: SF3D — 41 секунда против 8–11.
- Неудачи тоже описывайте. Ничего не приукрашивайте.
- Объём — 1–3 экрана текста, не считая раздела «Для видео».

## Картинки

- Картинки кладите в `img/` и нумеруйте по порядку рассказа: `01_problem.jpg`, `02_cause.png`,
  `05_before.jpg` + `05_after.jpg`.
- Формат: JPG с качеством 85–90 для рендеров и фото, PNG для интерфейса и схем. Ширина до 1920, файл до 600 КБ,
  вся папка `img/` — до 8 МБ.
- Под каждой картинкой — подпись в одну фразу: что на ней видно и куда смотреть.
- Пары «до/после» снимайте одной камерой, с одного ракурса, при одном свете и в одном размере кадра. Тогда в видео
  получится шторка. Если камеру не повторить, не делайте пару, а покажите кадры по отдельности.
- В `img/` можно рисовать стрелки, рамки и надписи. Тот же кадр без пометок положите в `src/`: стрелки в видео
  анимируются отдельно.
- Фон рендеров — ровный тёмно-серый или прозрачный. Модели снимайте спереди и в три четверти (поворот на 40°),
  серой глиной без текстуры и с текстурой.
- Готовые инструменты лежат в `_tools/`:
  - `render_models.py` (Blender) — модели одной камерой, 2560×1440, прозрачный фон;
  - `sheet.py` — лист сравнения с подписями для `img/`.

  Как их вызывать, написано в начале каждого файла. Блендер запускайте только через очередь `tool\blender_queue.py`:
  иначе параллельные сессии забирают весь процессор и у всех обрывается сеть.
- Схему (как устроен процесс) можно нарисовать блоком ` ```mermaid ` прямо в README: GitHub её покажет,
  а для видео её перерисуют.

## Для монтажа: case.json и src/

Это нужно, чтобы ролик собирался без повторного расследования.

- **Крупные чистые кадры** — в `src/`. Главные кадры — 2560×1440 (16:9), без надписей, лучше PNG с прозрачным фоном.
  `render_models.py` делает именно так.
- **Модели «до» и «после».** Пути к .glb или .blend укажите в `case.json → models`, сами модели в git не кладите.
  По ним снимут облёт камерой. Для облёта добавьте рост модели в метрах и поворот, при котором она смотрит в камеру.
  Если с файлом есть подвох, напишите: например, в нём нет нормалей и без них модель чёрная, или в него спрятан
  невидимый узел коллизии `*-colonly`, который браузер нарисует белым диском.
- **Цифры** «было / стало / единица» — в `case.json → numbers`. Из них строятся анимированные графики. У времени
  отметьте, первый это запуск или повторный.
- **Сцены** — 4–8 штук в `case.json → beats`: что сказать, что показать, сколько секунд. У сцены два текста:
  `say_ru` — как читать вслух (имена по-русски, числа словами), `sub_ru` — как писать на экране (цифры, латиница).
  Голос канала читает около 14,4 знака в секунду: на 1–2 минуты озвучки нужно 900–1700 знаков.
- **Как показать в приложении** — шаги по меню в `reproduce_in_app`, чтобы можно было записать экран.
- **Как пересобрать картинки** — команды в `regenerate`, если картинки сделаны скриптом.
- **Оценка для видео** от 1 до 5 и вау-момент: что зацепит зрителя.
- Запись экрана или короткий ролик (до 30 с) кладите в `src/*.mp4` и внесите в `media[]` с `"file": null`,
  `"kind": "clip"`.

## Нельзя

Репозиторий публичный, поэтому в разборе не должно быть:

- ключей, содержимого `tool/config.json`, почты;
- имени пользователя Windows в путях (`C:\Users\…`): пишите пути от корня проекта (`work/…`, `tool/…`) или с `D:\`;
- чужих картинок из интернета (лучше дайте ссылку);
- переписки с личными данными.

Интерфейс снимайте только на тестовом сервере с копией (порт 7891 и выше). Приложение пользователя (7890) и его
`export\` не трогайте.

## Как закоммитить

Коммитьте только свою папку, чужое из общего индекса не берите:

```powershell
git add -- "docs/Solve problems/<папка>"
git commit -m "Solve problems: <о чём>" -- "docs/Solve problems/<папка>"
```

Этот README, `_template/` и `_tools/` не правьте, предложения пишите в отчёте. Общий список разборов соберёт координатор.
